Pipeline: 2 creative agents (blue-sky + codebase-grounded) → merge/dedupe → 3 reviewer personas (Marketing, Design Purist, Delight & Novelty) → one revision round → re-scored → feasibility agent (codebase-grounded effort) → synthesis.

**Effort** = feasibility agent's implementation-difficulty score (1-5, 5 = hardest).

## Ideas

### 1. Duplicate as Template

**Pitch:** Let users duplicate an existing pass ("Use as template"/"Remix this pass") carrying over category, color, reminders, notes, and expiry settings while clearly marking the new copy as a draft that still needs a fresh code and label.

**Problem it solves:** Saves users from re-entering nearly identical metadata when creating a new pass based on an existing one (renewals, family variants, repeated pass types).

**Revision history:** Original pitch preserved category/color/reminders/notes and prompted only for changed code/label, framed as a smart convenience for recurring patterns. Changed because Marketing scored it low (2/5) as too narrow to move adoption; the revision repositioned it as a high-quality retention shortcut rather than an acquisition feature, and added warmer "remix" framing (Delight) plus an explicit "draft" marking so duplicated passes can never be mistaken for active ones (Design).

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 3/5):** Practical for a narrow but real set of repeat use cases, especially families and recurring pass types. Unlikely to move downloads or become a memorable differentiator, but useful once found.
- 🎨 **Design Purist (score: 5/5):** Sensible, low-drama productivity feature that fits naturally into a pass manager. The critical requirement is unmistakable draft status — met by the revision.
- ✨ **Delight & Novelty (score: 3/5):** "Remix this pass" gives it welcome personality; modest delight, saves effort and respects real habits.

**Feasibility (effort: 2/5):** `Pass` in `src/stores/passes.ts` already contains the fields to preserve (`categoryId`, `color`, `reminders`, `notes`, `expires`), and `PassDetailsForm.vue` already edits them as a reusable partial model — this is mostly a new action seeding `NewPassPage.vue` with a prefilled draft while clearing `data`/`label`.

**Scores:** Value **7.3/10** · Effort **2/5** · ROI **3.7**

### 2. Instant Present Mode

**Pitch:** Press-and-hold from a home-screen card jumps straight to a scan-ready fullscreen view, skipping the current Detail Page detour. Fullscreen controls are deliberately minimal: auto-max brightness, one "fit/fill" size toggle, existing pinch/rotate kept only as an optional fallback, and a subtle contrast halo for dim scanners.

**Problem it solves:** Removes unnecessary taps and presentation stress from the most time-sensitive moment in the app — getting a pass scanned quickly.

**Revision history:** Merges the grounded "Scan-Ready from Home" idea with the blue-sky "Magic Hand-Off" idea. Original combined pitch offered more elaborate gesture flourishes (rotate/mirror/halo). Changed because Design flagged that resize/rotate controls risked becoming "a mini editing surface during checkout" — the revision simplified fullscreen controls to one clear size toggle plus fallback gestures, keeping the core shortcut Marketing and Delight already rated a 5/5.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 5/5):** Users absolutely notice this — removes friction at the exact moment they're stressed and impatient. Drives strong satisfaction and "this app just gets it" reviews.
- 🎨 **Design Purist (score: 5/5):** Strong mobile coherence; press-and-hold is plausible on a card. The hold gesture must have crisp feedback so users never wonder if they're selecting, dragging, or presenting.
- ✨ **Delight & Novelty (score: 4/5):** Has the satisfying elegance of a magic trick — press, hold, boom, ready to scan. Delight comes from smooth competence.

**Feasibility (effort: 3/5):** Fullscreen presentation already exists in `FullscreenCodeViewer.vue` and pinch/rotate in `useTransformGestures.ts`, so the display core is there. The harder part is wiring press-and-hold from `CardStack.vue`/`PassCard.vue` without conflicting with existing tap/drag behavior, plus adding brightness/fit/halo controls that don't exist today.

**Scores:** Value **9.3/10** · Effort **3/5** · ROI **3.1**

### 3. Universal Find & Filter

**Pitch:** A progressive "Find" bar above the home stack, visually quiet by default, expanding into search and smart filter chips (name, code text, category, expiry state, "has reminders") only when tapped or when pass count grows. Zero-results states and chip labels carry a bit of personality.

**Problem it solves:** Makes retrieval fast once a collection outgrows casual browsing, without cluttering the home screen for lighter users.

**Revision history:** Original pitch added a search field and filter chips above the stack alongside existing category tabs. Changed because Design pushed toward progressive disclosure so search doesn't dominate the calm home screen too early; Delight's fair critique (useful but not delightful) was addressed by adding personality to chip language and zero-results states rather than forcing delight into the core mechanic.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 3/5):** Good product hygiene, increasingly important as collections grow, but nobody tells a friend about a search bar — supports retention, not a headline.
- 🎨 **Design Purist (score: 5/5):** Progressive disclosure is exactly right — quiet when small, powerful when scale demands it. Charm should stay extremely restrained relative to scanability.
- ✨ **Delight & Novelty (score: 3/5):** Sensible and keeps the home screen from turning into admin software, but still leans "competent" over "joyful."

**Feasibility (effort: 3/5):** `PassesPage.vue` currently only has category tabs and `passesStore` only computes `filteredPasses` by category, so text search/chips require expanding store selectors and home-screen UI — but the needed fields (`label`, `expires`, `reminders`, `categoryId`) already exist on `Pass`, making this contained Vue/Pinia work.

**Scores:** Value **7.3/10** · Effort **3/5** · ROI **2.4**

### 4. Expiry Attention System

**Pitch:** Fragmented expiry signals (badges, metadata, notifications) become one visible "Soon/Expired" inbox layer with snooze/edit/dismiss in one tap. Passes get a restrained "aging" treatment — subtle tonal shifts and clearer countdown labels — without tipping into melodrama.

**Problem it solves:** Gives users one coherent place to notice and act on expiring passes before a deadline is missed.

**Revision history:** Merges the grounded "Upcoming Expiry Inbox" idea with the blue-sky "Expiry Theatre" idea. Original combined pitch described passes "aging" through fresh → glowing → fading → urgent "last call" stages. Changed because Design warned that too much glow/fade/drama would undermine legibility and feel theatrical — the revision kept the metaphor (Marketing and Delight both confirmed visible urgency is what makes this memorable) but toned it down into subtle hierarchy and clearer countdown labels.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 3/5):** Turns passive decay into a manageable workflow — useful, but mostly a competence feature people expect rather than love.
- 🎨 **Design Purist (score: 5/5):** Clear upgrade — replaces scattered anxiety signals with one controllable workflow. Must stay subtle enough that cards don't look visually degraded.
- ✨ **Delight & Novelty (score: 3/5):** Admirably restrained; could give passes a faint sense of life. Delight here is subtle, mostly emotional relief.

**Feasibility (effort: 3/5):** Expiry already has solid foundations in `usePassExpiry.ts`, `ExpiredBadge.vue`, and reminder scheduling/snooze in `src/utils/reminders.ts` — the main work is a new actionable inbox view/route, persistence for snooze/dismiss state, and subtle aging styling in `PassCard.vue`.

**Scores:** Value **7.3/10** · Effort **3/5** · ROI **2.4**

### 5. Pocket Concierge

**Pitch:** A quiet "day companion" that suggests passes only when confidence is high and always shows why ("Near station," "Expires today," "Usually used at this time"). Home screen stays stable with a small optional "Likely next" rail rather than a reshuffling takeover; users can dismiss, pin, or correct suggestions in one tap.

**Problem it solves:** Users need faster access to the most relevant pass without a home screen that feels noisy, wrong, or invasive.

**Revision history:** Original pitch described a "cinematic" home screen that reassembled itself around live moments (commute, venue proximity, favorite store) with contextual backgrounds and countdowns. Changed because Marketing and Design both flagged the risk of overprediction and a "presumptuous" or "creepy" home screen — the revision narrowed the concept to selectively proactive, explainable suggestions in a small stable rail, preserving the anticipation Delight loved (5/5 originally) while making it feel trustworthy.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 4/5):** Smarter than the original — avoids the chaotic "smart home screen" trap. More of a retention enhancer than an acquisition hook.
- 🎨 **Design Purist (score: 5/5):** Much healthier than a takeover pattern — keeps spatial stability while adding anticipatory intelligence. Success hinges on the rail staying truly low-noise.
- ✨ **Delight & Novelty (score: 4/5):** More charming now because it helps without acting like it owns the home screen. Needs sharp copy/timing to feel delightful rather than merely well-behaved.

**Feasibility (effort: 4/5):** `PassesPage.vue` currently renders only category tabs plus `CardStack`, and `passesStore` exposes only `filteredPasses`, so a "Likely next" rail and suggestion persistence are net-new state/UI. No geolocation/calendar capability exists in `package.json`, so location-based confidence adds native/plugin work beyond a simple heuristic.

**Scores:** Value **8.7/10** · Effort **4/5** · ROI **2.2**

### 6. Scan-to-Story Capture

**Pitch:** A two-second identity layer, not a scrapbook — after scanning, ultra-light skippable prompts like "Add photo," "Use current place," or "Pick an emoji." The app auto-suggests human-friendly labels from context ("Airport lounge," "Bakery") for better recall with almost no extra work.

**Problem it solves:** Barcode data is hard to recognize later, and users need richer memory cues without slowing down capture.

**Revision history:** Original pitch framed this as building a "personal map of habits and adventures" through photos/notes/emoji moods attached at capture time. Changed because Marketing and Design both pushed on speed and optionality — the revision compressed the idea into ultra-light, skippable prompts and context-assisted auto-labeling, keeping the emotional warmth Delight scored highest (5/5) on both rounds.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 3/5):** Much better framing — lightweight memory support rather than journaling cosplay. A subtle utility boost, not a headline feature.
- 🎨 **Design Purist (score: 4/5):** Right instinct — respects scan momentum instead of interrupting it. Will feel polished only if every prompt is clearly optional and visually secondary.
- ✨ **Delight & Novelty (score: 5/5):** Exactly the light human touch wanted — tiny prompts, easy skips, a pass feels like *my* pass in seconds. Genuinely delightful.

**Feasibility (effort: 4/5):** `NewPassPage.vue` already has a clean scan → form flow and `PassDetailsForm.vue` already stores notes/reminders/category/color, so lightweight prompts fit the pattern — but photo capture, place attachment, and geolocation-based label suggestions aren't represented in `Pass` and need new schema plus missing native/web integrations.

**Scores:** Value **8.0/10** · Effort **4/5** · ROI **2.0**

### 7. Batch Add Sprint

**Pitch:** A "scan several" mode where each successful scan drops into a tightly structured, compact review queue (thumbnail, detected format, required label, quick category/color presets), with a crisp confirmation beat per scan, so importing many passes feels fast and controlled.

**Problem it solves:** Reduces repetitive form fatigue when users want to import multiple passes in one session.

**Revision history:** Original pitch described a looser "lightweight review queue" allowing users to skip full form completion during a scan burst. Changed because Design warned that deferred metadata could become a sloppy backlog if not tightly structured — the revision made the queue intentionally compact and disciplined; Delight's suggestion to add stronger moment-to-moment feedback led to the added "crisp confirmation beat" per scan.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 4/5):** Solves a real onboarding/import pain point for users moving from screenshots or paper clutter into one app — could materially improve activation.
- 🎨 **Design Purist (score: 4/5):** Operationally solid — "capture now, clean up in sequence" reduces context switching. Must stay visually calm and thumb-efficient, never spreadsheet-like.
- ✨ **Delight & Novelty (score: 4/5):** The confirmation beat is the spark — turns repetitive importing into a little rhythm of progress and control.

**Feasibility (effort: 4/5):** The current add flow in `NewPassPage.vue` is strictly single-item (`step: 'scanning' | 'form'`), so a scan-many review queue is a substantial flow rewrite needing new queue state, compact item editors, and deferred bulk save on top of `passesStore.addPass()`.

**Scores:** Value **8.0/10** · Effort **4/5** · ROI **2.0**

### 8. Pass Worlds

**Pitch:** Task-tuned modes built around recurring real-life contexts — Travel Day preloads tickets and gate-ready presentation, Coffee Loop stacks loyalty and payment-adjacent codes, Festival Mode surfaces multi-day entry passes with countdowns, Family Errands batches household passes. Visual identity stays light and consistent across the app; each world earns its existence through behavior, ordering, and retrieval shortcuts — not decoration.

**Problem it solves:** Users need organization that matches real situations and changes retrieval behavior, not just how passes look.

**Revision history:** Original pitch centered on immersive visual "worlds" (Night Out, Travel Day, Coffee Loop, Festival Mode) with soundtrack-like motion and shared color language per world. Changed because Marketing called it "aesthetic theater" and Design called it "dangerously ornamental" for a utility app — the revision made worlds behavior-first (preloading, ordering, shortcuts) and visually lighter, keeping the emotional framing Delight liked (4/5) only where it changes utility, not just looks.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 3/5):** Finally has a clearer reason to exist — context-specific retrieval speed, not "themes." Still risks fragmentation and feature-naming overhead.
- 🎨 **Design Purist (score: 4/5):** Fixes the biggest risk by grounding worlds in retrieval behavior. Still some "concept tax" risk if users must explicitly understand/switch worlds.
- ✨ **Delight & Novelty (score: 4/5):** Wisely kills costume-party theming; each context can feel quietly magical — "oh, it gets me" — if distinctions stay tangible.

**Feasibility (effort: 4/5):** Today the only behavioral context is category filtering via `categories.ts` + `selectedCategoryId`; ordering is manual drag via `useCardDrag.ts`/`reorderPasses()`. "Worlds" needs a new persisted mode model plus alternative ranking/shortcut behavior across `PassesPage.vue`, not just a visual toggle.

**Scores:** Value **7.3/10** · Effort **4/5** · ROI **1.8**

### 9. Ambient Queue Mode

**Pitch:** A presentation layer, not a separate mode — when PassDrop detects a likely high-pressure moment (boarding, checkout), it gently simplifies the current screen into a queue-ready state with larger touch targets, scanner-friendly brightness/contrast, subtle haptics, and an obvious next-pass rail, while staying recognizably PassDrop.

**Problem it solves:** Users need the app to become calmer, clearer, and easier to operate during stressful public scanning moments.

**Revision history:** Original pitch framed this as a distinct queue "mode" with giant controls and auto-advance. Changed because Design warned about mode proliferation and bolted-on special-case UI — the revision reframed it as an adaptive state of the existing UI rather than a separate mode, keeping the reassuring copy/haptics that Marketing and Delight both credited as the real product value.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 4/5):** Stronger now as a situational enhancement rather than a mode to learn. If detection is accurate, could feel distinctively polished; if it misfires, becomes annoying fast.
- 🎨 **Design Purist (score: 4/5):** As a presentation layer rather than a hard mode switch, much more coherent. Danger is over-detection reshaping the screen in the wrong moments.
- ✨ **Delight & Novelty (score: 5/5):** The app subtly shape-shifting around your stress without a new mode to learn — feels uncannily considerate when tuned well.

**Feasibility (effort: 5/5):** Cuts across `PassesPage.vue`, `ShowPassPage.vue`, `PassCard.vue`, and notification/haptics patterns. The detection side is the biggest lift — the codebase has no location/calendar/event pipeline today, so "likely high-pressure moment" needs new native integrations and app-wide reactive state.

**Scores:** Value **8.7/10** · Effort **5/5** · ROI **1.7**

### 10. Quick Actions on Cards

**Pitch:** A disciplined quick-action layer on home cards with only the highest-frequency tasks (Present, Edit, Move), revealed through one consistent gesture anchored to the existing card motion language — not a hidden-gesture puzzle.

**Problem it solves:** Cuts navigation overhead for common pass actions while preserving the clarity of the card stack.

**Revision history:** Original pitch offered a longer action set (Present, Edit, Rescan, Move Category, Delete) via long-press or swipe. Changed because Design warned that mixing long-press and swipe with too many commands gets crowded and conflict-prone — the revision cut the set down to the 3 highest-frequency actions and committed to one consistent reveal gesture.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 3/5):** Solid UX sharpening, not a growth story — useful but risks becoming invisible utility rather than consciously noticed value.
- 🎨 **Design Purist (score: 4/5):** Right discipline — limiting to true top-frequency actions and anchoring to existing motion language avoids gimmick territory.
- ✨ **Delight & Novelty (score: 3/5):** Glad this got disciplined — anchoring to card motion language gives satisfying physicality, more "pleasantly polished" than "genuinely charming."

**Feasibility (effort: 4/5):** Actions map well to existing capabilities (`ShowPassPage.vue` present/edit/category), but `CardStack.vue`/`useCardDrag.ts` already use pointerdown/tap/drag on the same surface — adding long-press or swipe without breaking reorder/tap behavior is the real implementation risk.

**Scores:** Value **6.7/10** · Effort **4/5** · ROI **1.7**

### 11. Trusted Vault

**Pitch:** Sensitive passes live behind standard biometrics/device auth first, with an optional "quick reveal ritual" as a playful accelerator rather than the primary lock. Users can long-press to peek, temporarily pin a vault pass, or recover instantly through clear fallback paths if a gesture fails or is forgotten.

**Problem it solves:** Users want sensitive passes protected without sacrificing reliability, recoverability, or confidence in urgent moments.

**Revision history:** Originally named "Secret Gesture Vault" — hiding passes behind custom personal gestures (drawn shapes, tap rhythms, tilt patterns) as the *primary* access method. Changed because Design scored this a 1/5 ("design smell") for using nonstandard gestures as the core access method for sensitive content — the revision moved primary trust to standard biometrics/device auth, kept the original gesture idea only as a secondary "reveal ritual" flourish, and added explicit recovery fallback (addressing Marketing's and Delight's reliability concerns).

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 4/5):** Right call making biometrics the main story — "fun gesture lock" was never a serious trust signal. Rarely drives buzz on its own.
- 🎨 **Design Purist (score: 4/5):** Prioritizing standard biometrics is absolutely the right hierarchy. The reveal ritual still risks tonal drift if it feels cute rather than efficient.
- ✨ **Delight & Novelty (score: 3/5):** Security first, playfulness second — smarter. Less whimsical than others, but more emotionally reassuring.

**Feasibility (effort: 5/5):** Passes are currently stored as plain JSON in `@capacitor/preferences` in `passes.ts`, with no concept of locked/hidden items or secure storage boundaries, and no biometrics plugin in `package.json` — biometric gating, per-pass hiding, and recovery UX would need new security architecture.

**Scores:** Value **7.3/10** · Effort **5/5** · ROI **1.5**

### 12. Private Backup & Restore

**Pitch:** An explicit backup and restore flow that bundles passes, categories, and settings into one privacy-first export, with optional encryption, clear file naming, and a sober restore preview that shows what will be imported before anything is changed.

**Problem it solves:** Removes the fear of losing carefully organized passes when the app is reinstalled or the user changes devices.

**Revision history:** Original pitch was largely the same shape (export/import with optional encryption and a restore preview). Changed only in tone/sharpening: Marketing and Design both confirmed trust is the real value here, so the revision leaned harder into clarity, file naming, and explicit preview rather than adding flourish — mostly kept as-is since the critiques confirmed its strength.

**Reviewer critiques (final, round 2):**

- 🎯 **Marketing (score: 4/5):** Builds trust and reduces adoption anxiety — valuable for reviews and converting cautious users, but a reassurance feature rather than a reason to excitedly install.
- 🎨 **Design Purist (score: 5/5):** Appropriately sober for a high-stakes flow; the restore preview is especially important. Export/import must stay ruthlessly simple or "privacy-first" becomes "ceremony-heavy."
- ✨ **Delight & Novelty (score: 2/5):** Trustworthy and mature, valuable, but delight is mostly absent — good product hygiene, low sparkle.

**Feasibility (effort: 5/5):** Persistence is currently split across separate `@capacitor/preferences` keys (`passes.ts`, `categories.ts`, `settings.ts`, `theme.ts`) with no unified import/export abstraction — a single-file backup with encryption, file picking/sharing, and safe restore/merge behavior needs new storage plumbing and native/web file APIs not currently present.

**Scores:** Value **7.3/10** · Effort **5/5** · ROI **1.5**
